# auto_cate — VOC 자동 카테고리 분류

비트버니(Bitbunny) 앱으로 들어오는 고객문의(VOC)를 정해진 기준으로 분류하고, "요즘 어떤 종류의 문의가 늘고 있는지"를 한눈에 보여주는 프로젝트입니다.

개발자가 아니어도 이 문서만 보면 프로젝트가 뭘 하는지, 어디서 결과를 보는지, 새 데이터가 생겼을 때 어떻게 하면 되는지 알 수 있도록 썼습니다.

---

## Quick Start

### 결과만 보고 싶다면
아래 링크를 열면 끝입니다. 별도 설치나 로그인이 필요 없습니다.

**공개 리포트 링크: https://carlie-dot.github.io/auto_cate-report/**

이번 주 카테고리별로 어떤 문의가 늘었는지, 표를 클릭하면 세부 항목(중분류·소분류)까지 펼쳐서 볼 수 있습니다.

### 새로 들어온 데이터를 반영하고 싶다면
1. VOC 원본 CSV 파일을 이 프로젝트의 `voc/` 폴더에 넣습니다.
2. 이 저장소가 열려 있는 Claude Code 세션에서 "새 파일 분류해줘" 또는 "최신화해줘"라고 요청합니다.
3. Claude가 분류하고, 위 공개 리포트를 최신 내용으로 다시 게시합니다. 완료되면 알려줍니다.

이 프로젝트는 "한 번 설치하면 알아서 도는 프로그램"이 아니라, **사람이 그때그때 요청해야 움직이는 수동 워크플로**입니다. 자세한 이유는 아래 "지금 안 되는 것"을 참고하세요.

## 프로젝트 오버뷰

| 항목 | 내용 |
|---|---|
| 무엇을 | 고객문의(VOC)를 8개 대분류(광고·코인·포인트·걸음수·계정·로그인·교환·앱 오류·일반문의·혜택)로 자동 분류 |
| 어떻게 | 키워드 규칙이 아니라, Claude(LLM)가 각 문의 내용을 직접 읽고 판단해서 분류 |
| 왜 | 어떤 유형의 문의가 늘고 있는지 빠르게 파악해서, 서비스 이슈를 더 일찍 발견하기 위함 |
| 결과 확인 | 링크 하나(웹페이지)로 확인 — 원본 파일이나 스프레드시트를 열 필요 없음 |
| 원문 노출 | 없음 — 화면에는 카테고리별 집계 수치만 나오고, 고객이 쓴 문의 원문은 보이지 않음(개인정보 보호) |

## 프로젝트 설명

1. **분류**: 고객이 보낸 VOC 데이터를 읽어서, 각 건을 대분류(예: "광고") → 중분류(예: "재생 중단") → 소분류(예: "진행 멈춤")까지 3단계로 분류합니다.
2. **비교**: 두 기간(예: 지난 주 vs 그 전 주)의 카테고리별 건수를 비교해서 어떤 카테고리가 늘었는지·줄었는지 보여줍니다. 아직 끝나지 않은 주(진행 중)의 수치는 "참고치"로 따로 표시해, 정식 비교와 헷갈리지 않게 합니다.
3. **게시**: 결과를 웹페이지 하나로 정리해서, 링크만 열면 누구나 볼 수 있게 합니다.

분류 기준은 [`docs/CATEGORY_TAXONOMY.md`](docs/CATEGORY_TAXONOMY.md)에 정의돼 있습니다(대분류 8개, 중분류 31개, 소분류 49개). 키워드나 정규식으로 자동 매칭하는 규칙 엔진은 쓰지 않습니다 — 매 건을 Claude가 이 기준표를 보고 직접 판단해서 분류합니다.

자세한 배경과 의사결정 과정(왜 이렇게 만들었는지, 무엇을 검토했다가 기각했는지)은 다음 문서에 남아 있습니다.
- [`docs/PRD.md`](docs/PRD.md) — 무엇을·왜 만들었는지
- [`docs/TRD.md`](docs/TRD.md) — 기술적으로 어떻게 만들었는지
- [`docs/DESIGN.md`](docs/DESIGN.md) — 화면을 어떻게 설계했는지
- [`docs/PLAN.md`](docs/PLAN.md) — 진행 단계와 현재 상태
- [`docs/LOG.md`](docs/LOG.md) — 날짜별 변경 이력

## 프로젝트 구조

이 프로젝트는 저장소 두 곳으로 나뉘어 있습니다.

- **작업용 저장소 (`carlie-dot/auto_cate`, 비공개)** — 실제 데이터·분류 코드·기획 문서가 있는 곳. 이 README가 있는 저장소입니다.
- **공개 결과 저장소 (`carlie-dot/auto_cate-report`, 공개)** — 위 공개 리포트 링크(GitHub Pages)만 서빙하는 별도 저장소. 원본 데이터나 내부 문서는 전혀 들어있지 않고, 결과 화면 파일 하나만 있습니다.

작업용 저장소(비공개)의 폴더 구성은 다음과 같습니다.

```
docs/                          기획·설계 문서 (PRD·TRD·DESIGN·PLAN·CATEGORY_TAXONOMY·LOG)
voc/                            VOC 원본·분류 결과 CSV (로컬 전용, git에는 안 올라감 — 실제 고객 데이터가 있는 폴더)
scripts/                        자동 실행을 위해 만들어둔 스크립트(현재 미해결 문제로 실제로는 미가동, 아래 한계 참고)
비트버니_문의분류체계.xlsx        분류체계 원본 파일(참고용, 실제 기준은 docs/CATEGORY_TAXONOMY.md)
CLAUDE.md                       이 프로젝트에서 지켜야 할 작업 규칙
README.md                       이 문서
```

## 사용법

**중요**: 이 프로젝트는 "설치하고 명령어 하나로 실행하는 프로그램"이 아닙니다. 상시 실행되는 서버나 자동 스케줄러가 없고, **Claude Code 세션에서 사람이 그때그때 요청해야 진행되는 수동 워크플로**입니다.

실제 진행 방식은 이렇습니다.

1. VOC 원본 데이터 파일(CSV)을 `voc/` 폴더에 넣습니다. 파일명은 기간을 나타내는 형식입니다(예: `20260901-20260906.csv`). 이 폴더는 `.gitignore`로 제외되어 있어 GitHub에는 올라가지 않습니다 — 원본 데이터는 항상 로컬에만 있습니다.
2. 이 저장소를 열어둔 Claude Code 세션에서 "분류해줘", "최신화해줘", "지난 주랑 비교해줘" 같은 요청을 합니다.
3. Claude가 `docs/CATEGORY_TAXONOMY.md` 기준으로 각 건을 분류하고, 결과를 원본 옆에 `_classified.csv` 사본으로 남깁니다(원본 파일 자체는 건드리지 않음).
4. 집계 결과를 비공개 아티팩트(팀 내부 확인용)와 공개 리포트 링크(위 Quick Start 참고) 양쪽에 갱신해서 게시합니다.

즉 "실행"은 곧 "이 저장소를 열어둔 채로 Claude에게 요청하는 것"입니다. 별도의 실행 파일이나 실행 버튼은 없습니다.

## 지금 안 되는 것 (한계)

- **자동/주기적 실행이 아직 불안정함**: 하루 2번(오전 10시·오후 6시) 자동으로 확인하도록 만들어뒀지만, 실제로는 작동하지 않는 문제가 있어 지금은 매번 사람이 요청해서 처리하고 있습니다.
- **"진짜 이번 주 vs 지난 주" 비교는 아직 못 함**: 지금까지의 비교는 데이터가 확보된 가장 최근으로 완성된 두 주를 비교한 것이지, 달력상 "이번 주"가 다 끝난 뒤의 진짜 비교는 아닙니다. 해당 주가 실제로 끝나야 계산할 수 있습니다.
- **리포트 자동 재게시 없음**: 새 데이터가 들어와도 저절로 화면이 갱신되지 않습니다. 요청이 있어야 다시 게시합니다.
- **문의 원문은 화면에 안 보여줌**: 결과 페이지에는 카테고리별 건수·비율만 나오고, 고객이 실제로 쓴 문의 원문은 노출하지 않습니다(개인정보 보호 목적, 의도된 설계입니다).
- **분류 결과의 전수 검증 없음**: 일부 샘플만 사람이 확인했고, 나머지는 검증되지 않은 상태입니다. 정답 라벨을 기준으로 한 정확도 측정 체계도 없습니다.
- **일부 문의 유형은 분류 기준에 아직 없음**: 예를 들어 "사기성 광고", "지급액 불일치" 같은 유형은 정확히 맞는 카테고리가 없어 가까운 카테고리에 임시로 넣어둔 상태입니다([Issue #1](https://github.com/carlie-dot/auto_cate/issues/1) 참고).
- **원본 분류체계 파일(xlsx)은 자동으로 동기화되지 않음**: 실제 분류 기준은 `docs/CATEGORY_TAXONOMY.md`이고, 원본 `비트버니_문의분류체계.xlsx`와는 사람이 확인해야만 맞출 수 있습니다.
